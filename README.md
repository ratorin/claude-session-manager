# Claude Session Manager

[Claude Code](https://claude.com/claude-code) の会話履歴・メモリ・エージェントを管理する VS Code 拡張機能。

ブックマーク、タグ付け、メモ、Markdownプレビュー、エージェント管理、組織図など、Claude Code本体にない会話・エージェント管理機能を提供します。

---

## 主な機能

### 会話管理

- **会話一覧** — 全プロジェクトの会話を日付別（今日/昨日/今週/今月/それ以前）に自動分類
- **モデル表示** — モデル頭文字（Ｏ=Opus / Ｓ=Sonnet / Ｈ=Haiku）とメッセージ件数を表示
- **プレビュー** — チャット形式で会話内容を表示。Markdownレンダリング対応（コードブロック・テーブル・見出し・リスト）
- **リンクのクリック対応** — プレビュー内のURLはブラウザ、Windowsファイルパスはエディタで開く（行番号ジャンプ付き）
- **ブックマーク** — 大事な会話をお気に入り登録。専用セクションに一覧表示
- **タグ** — 自由なカテゴリで分類。タグ別グループ表示
- **メモ** — 各会話に役割や目的のメモを記入可能。500ms遅延で自動保存
- **リネーム** — 会話にわかりやすい名前を設定。Claude Code側と双方向同期
- **検索** — タイトル・プロジェクト・ブランチ名でフィルタ
- **Claude Codeで開く** — 右クリックからVS CodeのClaude Codeパネルで会話を再開（Antigravity等フォーク対応）
- **セッションIDコピー** — 右クリックからセッションIDをクリップボードにコピー
- **セッションパスをコピー** — 右クリックからJSONLファイルのフルパスをコピー（他エージェントに読ませる際に便利）

### ライブセッション検出

- Claude Codeで現在使用中のセッションをリアルタイム検出
- 使用中の会話は緑の **●** アイコンで表示
- PID生存チェックでゾンビセッションも自動クリーンアップ（ポーリングは設定でON/OFF切替可能、デフォルトOFF）

### 子エージェントのツリー表示

- セッション配下の子エージェント（`subagents/` フォルダ内の JSONL）を自動検出
- 親セッションを展開すると子エージェントをツリー表示
- タイプ別アイコン: 🔍探索 / 📋計画 / 🔧汎用 / 📖ガイド

### エージェント管理

- **エージェント登録** — セッションを右クリック → 「エージェントとして登録」
  - Webviewフォームで部署名・役割・モデル・セッション運用（固定/使い捨て）・スコープ・上司・作業フォルダを一括入力
  - カード型ラジオボタンでモデル・運用モード・スコープを選択、フォルダ選択ダイアログ連携
  - ルールファイルはスコープ（プロジェクト/グローバル）に基づいて保存時に自動生成
- **エージェントプレビュー** — エージェント一覧でクリックすると読み取り専用プレビューを表示
  - 名前・モデル・上司・役割・子エージェント一覧・ルールファイル内容を確認
  - 「設定」ボタンで編集フォームに切り替え
  - セッション名リンクからセッション履歴プレビューへ遷移
- **エージェント管理サイドバー** — 登録済みエージェントの一覧表示
  - ライブ状態（🟢/⚪）・モデルバッジ・ルールファイル行数/サイズを表示
  - 使い捨てエージェントは「使い捨て」ラベル表示
  - 右クリックからセッション紐づけ・設定編集・ルールファイル編集・削除
  - 子を持つエージェント（上司）がツリーの上位に表示
- **セッションを開く** — 紐づけ済みエージェントのセッションをClaude Codeで開く
- **セッションを新しくする** — 簡易（即時抽出）/詳細（AI要約）の2モードで遺言を生成し、ルールファイルに歴代記録として蓄積（直近3世代保持・過去ID5件追跡）
- **設定編集** — 登録済みエージェントの設定を既存値表示のまま編集
- **ルールファイル編集** — 右クリックから直接エディタで開く
- **プレビューヘッダのバッジ** — 登録済みエージェントのセッションにモデル・名前・役割を表示。「設定編集」「ルールファイル」リンク付き
- **セッション一覧のエージェント名** — 登録済みセッションの description に `🤖部署名` を表示

### タスク管理・状態検知・通知

- **タスクログ** — エージェントに割り当てたタスクの状態を自動追跡
  - AgentWatcher イベントで自動評価（新しいポーリングループなし）
  - PID生存 + sessions/*.json mtime で running/stalled/completed を判定
  - stalled 閾値: 60秒（設定変更可能、Extended Thinking対応）
- **ツリー表示** — エージェントの子ノードとしてタスクログを表示
  - ステータス別アイコン（実行中/応答停止/完了/エラー/待機）と経過時間
- **VS Code通知** — タスク完了・エラー・応答停止をリアルタイム通知（60秒間隔制限でフラッピング防止）
- **自動クリーンアップ** — completed/error は 72時間、running/stalled/pending は 168時間で自動削除
- **自動検出** — AgentWatcherイベントで自動的にタスク状態を検知（手動操作不要）

### 組織図・ステータスバー

- ステータスバー（左下）に常時 `👥 M`（登録総数）を表示。`enableAgentMonitor: true` 時は `🟢 N 👥 M`（動作中数+登録総数）をリアルタイム更新し、動作中エージェントがいるときは背景色で強調表示（デフォルトOFF）
- **AgentWatcher統合監視** — PIDベースのライブセッション検出 + JSONL解析によるサブエージェント検出を1モジュールに統合。EventEmitter方式で変更時のみUIを更新
- エージェント一覧は稼働中が自動で上にソートされる
- ホバーで動作中エージェント名リストをツールチップ表示
- クリックすると Webview パネルで組織図を表示
- 各カードにモデルバッジ・役割・セッション状態を表示
- **🕐 ボタン** でカードから会話履歴をプレビュー
- **スパークアイコンボタン**（オレンジ角丸背景）でカードから Claude Code でセッションを直接開く

### ソート・グループ化

- **ソート** — 日付（新/古）・名前・メッセージ数・モデルで並び替え
- **グループ切替** — 日付別（デフォルト）/ タグ別 / エージェント別 / フラット（グループなし）
- ビュータイトルバーのボタンからワンクリックで切替

### セッション削除

- 不要なセッションを右クリック → 「セッションを削除」
- ファイルは `~/.claude/.trash/` に移動（完全削除はしない）
- 紐づき済みエージェントがある場合は紐づけ解除の確認あり
- ブックマーク・タグ・メモ・カスタム名も同時にクリーンアップ

### 初期セットアップ

- 取締役登録時にVS Codeの `extensions.experimental.affinity` 設定を自動追加（Extension Hostプロセス分離）
- CSMとClaude Code拡張機能を別プロセスで動作させ、パフォーマンスを向上

### ウェルカム画面

- エージェント未登録時のみ「取締役を登録」ボタンを表示（登録後は非表示）
- 取締役プリセット（Opus・固定・全体統括）で即座に開始可能

### メモリ管理

- **メモリ一覧** — タイプ別バッジ（user / feedback / project / reference）付きで表示
- **グローバルメモリ表示** — `~/.claude/memory/` 配下のメモリファイルもツリーに表示
- **設定ファイルビューワー** — `settings.json` / `settings.local.json` をメモリツリーのトップに表示、クリックでエディタで開く
- **プロジェクトをVS Codeで開く** — メモリツリーのプロジェクトグループを右クリック → 「VS Codeで開く」
- **容量表示** — インジケーターバー付きインデックス使用率（最大200行）。空き部分は「─」、右端は「|」で表現
- **プレビュー・編集・統合・抽出・削除**
- **メモリパスをコピー** — 右クリックからファイルパスをコピー（他エージェントに読ませる際に便利）
- **OneDrive対応** — 日本語を含むOneDriveパスのプロジェクト名を正しく表示

### セッションフィルター

- ビュータイトルバーのフィルターアイコンでプロジェクト内のセッションのみ / すべてのセッションを切替表示

### ルールファイル（YAML Frontmatter）

- エージェントの設定情報をルールファイル冒頭の YAML Frontmatter に格納
- `description` フィールドに自動生成テキスト、`---` 以下はユーザーが自由に編集可能
- 旧形式（`<!-- CSM:AUTO -->` マーカー）は更新時に自動移行

```yaml
---
name: CSM開発部
model: sonnet
effort: high
description: |
  あなたはCSM開発部所属のエンジニアです。
---

（ここから自由に記述）
```

### SubagentStart/Stop フック

- Claude Code の SubagentStart / SubagentStop イベントでシグナルファイルを出力
- シグナルディレクトリ: `~/.claude/.csm-signals/`
- 取締役セットアップ時に `settings.json` へ自動登録（`ensureSubagentHooks()`）
- 5分超の古いシグナルファイルを自動クリーンアップ

### マイグレーションバナー

- 旧形式ルールファイル検出時にエージェント管理ツリー上部に⚠バナーを表示
- クリックで YAML Frontmatter 変換 + フォルダ構造移行を一括実行
- 移行完了後バナーは自動非表示

### エージェントフォーム拡張

- **推論努力レベル（Effort）** — Low / Medium / High / Max の4段階（MaxはOpus専用でグレーアウト連動）
- **Extended Thinking** — トグルスイッチでON/OFF（Haikuではグレーアウト）
- **モデル別UI連動** — モデル選択に応じてEffort Max / Thinking のグレーアウトが自動切替

## クイックスタート

### 1. インストール後

VS Code 左のアクティビティバーに 💬 アイコンが表示されます。クリックすると5つのセクションが表示されます:

- **会話一覧（セッション）** — すべてのClaude Code会話
- **会話ブックマーク** — お気に入り登録した会話
- **会話タグ** — タグ別に分類した会話
- **エージェント管理** — 登録済みエージェントの一覧
- **メモリ管理** — Claude Codeのメモリファイル

### 2. エージェントを登録する

1. 会話一覧からエージェント用のセッションを見つける
2. 右クリック → 「エージェントとして登録」
3. フォームに従って入力:
   - **部署名** — エージェントの識別名（例: CSM開発部）
   - **役割** — 担当業務（例: TypeScript開発・品質管理）
   - **モデル** — opus / sonnet / haiku から選択
   - **セッション運用** — 固定（同じセッションを使い続ける）/ 使い捨て（タスクごとに新セッション）
   - **スコープ** — プロジェクト（ワークスペース内）/ グローバル（~/.claude/配下）
   - **親エージェント** — 階層構造がある場合に親を選択
   - **作業フォルダ** — エージェントの作業ディレクトリ
4. ルールファイルはスコープに基づいて自動生成されます

### 3. 組織図を確認する

ステータスバー左下の「👥 登録数」表示をクリックすると、登録済みエージェントの組織図が開きます。

### 4. エージェントを管理する

- **エージェント管理サイドバー** で一覧を確認
- 右クリックで設定編集・セッション紐づけ変更・削除

## エージェント運用ガイド

### 1. 取締役の登録

マルチエージェント運用の第一歩は、全体を統括する「取締役」エージェントを登録することです。

- エージェント管理のウェルカム画面から「取締役を登録」をクリック
- **モデル**: Opus（高度な判断・指示出しが必要なため、最上位モデルを推奨）
- **セッション運用**: 固定（長期的な文脈を保持するため）
- **役割**: 全体統括・タスクの分割・指示出し・承認判断
- 取締役はルールファイルで「行動規範」「禁止事項」「判断基準」を定義しておくと効果的

### 2. 部署（子エージェント）の追加

取締役の下に、業務内容に応じた部署（子エージェント）を追加します。

- 会話一覧から対象セッションを右クリック → 「エージェントとして登録」
- **親エージェント**: 「取締役」を設定（組織図でツリー表示される）
- **モデルの使い分け**:
  - 重要な判断・設計タスク → Opus
  - 通常の開発・実装タスク → Sonnet
  - 定型作業・軽量タスク → Haiku（コスト効率が高い）

| 部署名 | モデル | 役割 |
|--------|--------|------|
| CSM開発部 | Opus / Sonnet | 機能実装・コードレビュー |
| テスト部 | Sonnet | テスト設計・自動化 |
| 調査部 | Sonnet | 技術調査・情報収集 |
| 雑務部 | Haiku | ドキュメント生成・定型作業 |

### 3. ルールファイルの育成

各エージェントにルールファイル（.md）を設定し、役割・行動規範・ノウハウを蓄積します。

- エージェントを右クリック → 「ルールファイルを編集」で直接編集
- 初期はひな形を自動生成し、運用しながら育てる
- フィードバックやノウハウを追記して成長させる
- ルールファイルはセッションをまたいで引き継がれる **長期記憶** として機能する

### 4. セッションの引き継ぎ

コンテキストウィンドウの上限に達したらセッションを更新します。

- エージェントを右クリック → 「セッションを新しくする」
- 遺言の生成方法を選択: **簡易（即時）** または **詳細（AI要約）**
- 生成された遺言をInputBoxで確認・編集
- 遺言はルールファイルの「歴代セッションの記録」に自動蓄積（直近3世代）
- 新セッションはルールファイル経由で過去の経緯を自動的に把握

### 5. おすすめ構成例

**取締役 → 部署 → 班** の三階層構造:

```
取締役（Opus・固定）— 全体統括・タスク分割・最終判断
  ├── 開発部（Opus・固定）— 実装・レビュー・設計
  │     ├── 実装班A（Sonnet・固定）
  │     └── 実装班B（Sonnet・固定）
  ├── テスト部（Sonnet・使い捨て）— テスト設計・自動化
  ├── 調査部（Sonnet・使い捨て）— 技術調査・情報収集
```

## 設定項目

VS Code の設定画面（`Ctrl+,`）から `claudeManager` で検索して変更できます。

### エージェント監視

| キー | 型 | デフォルト | 説明 |
|---|---|---|---|
| `enableAgentMonitor` | boolean | false | エージェント監視を有効化（ステータスバーにリアルタイム表示） |
| `agentMonitorInterval` | number | 5 | エージェント監視の更新間隔（秒） |
| `enableNotifications` | boolean | true | タスク完了・エラー・停止時の通知を有効化 |
| `taskStalledThreshold` | number | 60 | 応答停止（stalled）判定の閾値（秒） |
| `taskAutoCleanupHours` | number | 72 | 完了/エラーのタスクログを自動削除するまでの時間 |
| `taskMaxLogs` | number | 100 | 保持するタスクログの最大件数 |
| `enableUsageMonitor` | boolean | false | Claude Code利用制限をステータスバーに表示 |
| `usageMonitorInterval` | number | 300 | 利用制限モニターの更新間隔（秒） |

### セッション表示

| キー | 型 | デフォルト | 説明 |
|---|---|---|---|
| `defaultSortMode` | enum | updated-desc | デフォルトのソート順 |
| `defaultGroupMode` | enum | date | デフォルトのグループ化 |
| `maxSessionsShown` | number | 500 | 表示する最大セッション数 |
| `sessionFilterMode` | enum | all | プロジェクト内のみ / すべて |

### その他

| キー | 型 | デフォルト | 説明 |
|---|---|---|---|
| `defaultRuleFolder` | string | "" | ルールフォルダパス |
| `preview.showThinkingBlocks` | boolean | false | AIの思考過程をプレビューに表示 |
| `trash.folder` | string | "" | ゴミ箱フォルダパス |
