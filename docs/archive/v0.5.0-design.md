## 1. 概要・ゴール

### 1.1 v0.5.0の目玉と狙い

| 主題 | 狙い | KPI / 完成基準 |
|---|---|---|
| 3タブ統合UI | 役割の異なる視点を「セッション/エージェント/プロジェクト」で明確に切り分け、メインビューを整理する | サイドバービュー数 5 → 3 ／ ユーザーが目的のビューに辿り着くクリック数 平均-30% |
| プロジェクト管理 | 「いま何のプロジェクトを進めているか」「誰がどこで動いているか」を一目で見る | プロジェクト一覧の表示時間 < 1.5s ／ 紐づけ操作 3クリック以内 |
| 組織図リニューアル | 既存ツリーが陳腐化＆視認性低下 → 拡張可能・インタラクティブな図に | 100エージェント規模で 60fps 描画 ／ ノードクリック→詳細パネル < 100ms |
| 日本語フレンドリー | 海外発スキル/エージェントを母語で扱える | 既知エージェント・スキルの 95% に日本語表示が出る |
| クロスプラットフォーム | Win/Linuxで同一プロジェクトを行き来 | パス変更検知 → リンク再構築まで完全自動化 |
| 自律組織構築 | マネージャーが組織を成長させられる | 提案→ユーザー承認→生成のループが稼働 |

## 3. データモデル

### 3.1 Project（合成定義）

```typescript
// src/models/types.ts に追加
export interface ProjectDef {
  id: string;                    // safe-id (slug化したパス)
  name: string;                  // 表示名（日本語可）
  rootPath: string;              // 絶対パス
  source: ('workspace' | 'claude-projects' | 'manual')[];  // 由来（複数可）
  hasClaudeDir: boolean;         // .claude/ 配下が存在するか
  claudeProjectKey?: string;     // ~/.claude/projects/ 配下のキー
  pinned?: boolean;              // ピン留め（カードを上に表示）
  description?: string;          // ユーザー入力の説明
  tags?: string[];               // プロジェクトタグ
  agents: string[];              // 紐づけエージェント名（明示割り当て）
  lastOpenedAt?: number;         // 最終アクセス時刻 (ms)
  createdAt: number;
  updatedAt: number;
}

// data/projects.json
export interface ProjectStore {
  version: 1;
  projects: ProjectDef[];
  recents: string[];             // 最近開いた project.id 5件
}
```

**プロジェクトの "発見" ロジック**:
- ① VS Code の `vscode.workspace.workspaceFolders` を全件取得
- ② `~/.claude/projects/<key>/` の各ディレクトリ名から元パスを復元（key は cwd を `/` → `-` で平坦化したもの）
- ③ ユーザーが `manual` で追加したパス
- ④ 上記をマージ → 同一 `rootPath` をユニオン化 → `source[]` に由来を記録

## 4. 機能詳細（13項目）

### F1. 3タブUI

| 項目 | 内容 |
|---|---|
| 実装 | `claudeMain` を **WebviewView**（Container）にし、上部にタブバー（HTML/CSS/JS）。タブ切替時は内部 div を出し分け |

| アイコン | `$(comment-discussion)` / `$(organization)` / `$(folder-library)` |

### F2. プロジェクト定義（合成）

| 項目 | 内容 |
|---|---|
| 由来 | `workspaceFolders[]` ＋ `~/.claude/projects/<key>/` ＋ `manual` |
| キー復元 | `~/.claude/projects/-mnt-hgfs-Project-foo/` → `/mnt/hgfs/Project/foo` （`-` → `/` で逆変換、Windowsは `C--xampp-...` ） |
| 同一判定 | 正規化パス（NFC、case-fold on Windows）で比較 |
| マージ | 同一 `rootPath` を1つの `ProjectDef` に統合し `source[]` に複数由来を記録 |
| 信頼度 | `hasClaudeDir = true` && `source includes 'workspace'` を「アクティブ」、それ以外を「履歴のみ」と表示分岐 |

### F5. 組織図リニューアル

| 項目 | 内容 |
|---|---|
| ライブラリ | **Cytoscape.js + ELK レイアウト** （理由：双方向関係対応・MIT・100ノード規模で60fps） |
| 代替案 | Mermaid（描画品質劣化）/ D3（実装重）/ ReactFlow（React依存重） |

| エッジ | 親子（実線）／連携（点線）／管理委譲（太線） |
| インタラクティブ | クリック→詳細パネル / ダブルクリック→編集 / 右クリック→コンテキスト |
| フィルタ | プロジェクト / モデル / 役割 |
| エクスポート | PNG / SVG ボタン |
| 保存 | レイアウトを `data/orgchart-layout.json` にキャッシュ |

### F6. 使用率バー Sonnet 5d 列追加

|---|---|
| 形式 | `5% 4.5h / S 3% 5d20h / O 20% 5d10h` |

### F7. /csm-ask-agent workDir 緩和

| 項目 | 内容 |
|---|---|
| 旧仕様 | workDir と current workspace が完全一致のみ許可 |
| 新仕様 | **`isContainedIn(workspace, workDir)` または `isContainedIn(workDir, workspace)` のいずれか真**で許可 |
| 実装場所 | `templates/csm-ask-agent.py` + `src/utils/cliBuilder.ts` |
| エラー出力 | 「workDir(/a/b) is outside workspace(/c). Set claudeManager.askAgent.allowAnyWorkDir=true to disable check.」 |

### F8. プロジェクト専任エージェントの視認性

| カテゴリ | 表示ルール |
|---|---|
| グローバル (scope=global) | **全プロジェクトで表示**＋🌐バッジ |
| プロジェクト (scope=project, projectIds=[A]) | **プロジェクトAをアクティブ時のみ表示** ／他プロジェクト時は「他プロジェクトのエージェントを表示」トグルでON時のみ |
| 設定 | `claudeManager.agents.showOtherProjects: boolean` (default: false) |
| 子エージェント | 親が表示対象なら子も同条件で表示 |

### F9. クロスプラットフォーム引っ越し対応強化

| 機能 | 内容 |
|---|---|
| F9-a パス解決 | `~`/`${HOME}`/`${USERPROFILE}`/`${PROJECT_DIR}` を実行時解決する `pathUtils.expand()` |
| F9-b 設定の相対化 | 保存時は `~/foo` 形式、読込時に絶対化 |
| F9-c JSONLリンカー | workDir 変更を検知すると `~/.claude/projects/<oldKey>/` → `<newKey>/` を再リンク（symlink ＞ hardlink ＞ copy fallback） |
| F9-d 引っ越しウィザード | コマンド `claudeManager.relocateProject` で旧パス→新パスを指定 → 全エージェント・JSONL・設定を一括更新 |

## 8. リスク・未決事項

> ⚠ ユーザー（director経由）への確認が必要な項目には `[要確認]` を付与。

### R1. Webview vs TreeView ハイブリッド設計の限界 `[要技術検証]`

**懸念**: VS Code Webview と TreeView は同居しづらい。タブ内で TreeView をそのまま使う方法が無いため、Webviewから TreeView の代替（HTML lists）を再実装する必要があるかもしれない。

**選択肢**:
- (A) ハイブリッド：タブヘッダだけWebview、本体は今まで通り別 TreeView を切替表示（操作性○、見た目△）
- (B) 完全Webview：本体もWebviewで HTML/CSS リスト再実装（見た目◎、操作実装コスト×）

**推奨**: Sprint 1の T1.9 段階で **プロトタイプ** を作成して判断。本書では (A) を前提に書いているが (B) もありうる。

### R2. 組織図ライブラリ選定 `[要確認]`

**候補比較**:
| ライブラリ | 評価 |
|---|---|
| Cytoscape.js + ELK | ◎ 双方向・大規模・MIT。本書の推奨 |
| Mermaid | △ 静的描画は綺麗だがインタラクティブ操作が貧弱 |
| D3 | △ 自由度高いが実装コスト大 |
| ReactFlow | × React依存 |

**推奨**: Cytoscape.js。要承認。

### R3. 自動翻訳のコスト `[要確認]`

Anthropic API（Haiku 4.5 想定）でエージェント定義を翻訳する場合、1件あたり 200〜500 トークン × 入出力 = 約 $0.0002 〜 $0.0005。100件で $0.05 程度。
**質問**: デフォルトでON（自動翻訳）にしてよいか？ それともユーザー明示ONか？ 本書では **明示ON** を前提に設計。

### R4. プロジェクトキー復元の信頼性 `[要技術検証]`

`~/.claude/projects/<key>/` の key 形式が Claude Code のバージョンによって変わる可能性。`-mnt-hgfs-Project-foo` 形式の正規表現で復元するが、仮想ドライブやUNCパス（`\\server\share\foo`）でテストが必要。

### R5. 自律組織のセキュリティ `[要確認]`

親エージェントが配下を作成・解任できる仕様は、プロンプトインジェクションで「director を解任せよ」と指示されるリスクがある。
**緩和策**:
- `guarded: true` のシステムエージェントは API レベルで操作不可
- 自律生成は **必ずユーザー承認モーダル** を経由
- 監査ログ `org-history.jsonl` は変更不可属性で書き出し
**質問**: ガード対象エージェントのリストはユーザーが編集可能にすべきか？

### R6. プロジェクト紐づけの "他プロジェクト時に表示しない" 範囲 `[要確認]`

エージェントが scope=project かつ projectIds=[A] で、ユーザーが workspace=B にいる場合：
- (A1) **完全に非表示**（クリーン）
- (A2) "他プロジェクトのエージェント" セクションに格納し折りたたみで隠す（情報残）
- (A3) 設定で切替

本書では **(A2)** をデフォルト、`showOtherProjects` 設定で切替。要確認。

### R7. データマイグレーションの後方互換 `[要決定]`

v0.4.5 → v0.5.0 でファイル形式が変わる項目：
- `data/global-agents-i18n.json` → `data/i18n/ja/agents.json` （移動）
- `session-manager.json` → スキーマ拡張（フィールド追加のみ・後方互換あり）
- 新規： `data/projects.json` `data/bookmarks-agents.json` `data/last-used.json`

**自動マイグレーション** を行うが、失敗時は **バックアップを `data/.backup-v0.4.5/` に作成** してから書き換え。質問：マイグレーション失敗時に「v0.4.5 にロールバック」する仕組みは必要か？

### R8. 引っ越し時のシンボリックリンク権限 `[要技術検証]`

Windows で symlink を作るには管理者権限または Developer Mode 有効化が必要。
**フォールバック順**: symlink → hardlink → copy。Linux/Mac は symlink 一択。要動作確認。

### R9. パフォーマンス：プロジェクト 100件・エージェント 200件 規模 `[要技術検証]`

プロジェクトタブ初期表示 < 1.5s を目標とするが、JSONLスキャンが重い場合がある。

## 9. マイグレーション

### 9.1 自動移行スクリプト

起動時 (`extension.activate()` の最初) に以下を実行：

```typescript
async function migrateToV050(): Promise<void> {
  const v = await dataStore.getVersion();
  if (v >= '0.5.0') return;

  // バックアップ
  await fs.cp('data/', 'data/.backup-v0.4.5/', { recursive: true });

  // 1. i18n 移動
  await fs.rename('data/global-agents-i18n.json', 'data/i18n/ja/agents.json');

  // 2. プロジェクト発見 → projects.json 生成
  const discovered = await projectService.discover();
  await dataStore.saveProjects(discovered);

  // 3. session-manager.json スキーマ更新（フィールド追加のみ）
  const agents = await dataStore.getAgents();
  for (const a of agents) {
    a.scope = a.scope || 'global';
    a.bookmarked = false;
    a.lastUsedAt = a.lastUsedAt || 0;
  }
  await dataStore.saveAgents(agents);

  // 4. 新規ファイル
  await fs.writeFile('data/bookmarks-agents.json', JSON.stringify({ version: 1, bookmarks: [] }));
  await fs.writeFile('data/last-used.json', JSON.stringify({ version: 1, records: {} }));

  await dataStore.setVersion('0.5.0');
  vscode.window.showInformationMessage('CSM v0.5.0 へのマイグレーションが完了しました。');
}
```

### 9.2 ユーザー視点の影響

|---|---|
