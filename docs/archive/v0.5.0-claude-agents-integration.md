# CSM v0.5.0 — `claude agents` コマンド統合設計書（案B：統合表示）

> **版数**: Draft v1.0
> **作成日**: 2026-05-14
> **作成者**: csm-planner
> **対象**: Claude Code 2.1.139 以降で導入された `claude agents` コマンドを CSM サイドバーに統合
> **採用方針**: 案B（統合表示） — CSM 独自機能を維持しつつ、`claude agents` のライブ状態を埋め込む
> **関連**: [`v0.5.0-design.md`](./v0.5.0-design.md), [`v050-menu-redesign.md`](./v050-menu-redesign.md)

## 0. エグゼクティブサマリ

- Claude Code 2.1.139+ で **`claude agents`** がリリースされ、全 Claude Code セッションの running/blocked/done を1リストで表示できるようになった
- CSM 既存機能（履歴・メモリ・組織図）と重複する範囲があるが、CSM は **永続データ＋メタ管理** を担い、`claude agents` は **ライブ瞬間状態** のみを担うので **役割分担で共存可能**
- **採用方針：案B（統合表示）** ― CSM 内で `claude agents` 結果を取り込み、エージェントタブ最上部に「🟢 ライブ状態」セクションとして表示
- **実機調査結果（2026-05-14 確認）**：
  - 利用可能なオプションは `--cwd <path>` と `--setting-sources` のみ
  - **`--json` オプションは存在しない** → テキスト出力のパースが必要
  - 実行できない環境がある（`'claude agents' is not available in this environment.`）→ **可用性検出が必須**

## 1. 設計目標

### 1.1 ユーザーストーリー

> **US-1**：CSM ユーザーとして、「今この瞬間に稼働中のエージェント」を VS Code を離れずに見たい。
>
> **US-2**：ライブ表示の行をクリックしたら、その場で CSM の既存セッションプレビューが開き、履歴やメモリと連動して見たい。
>
> **US-3**：`claude agents` が使えない環境（古いバージョン／非対応シェル）でも CSM 本体は壊れず動いてほしい。
>
> **US-4**：ポーリングのオーバーヘッドが気になる場合は無効化したい。

### 1.2 達成基準（KPI）

| 指標 | 目標値 |
|---|---|
| ライブセクションの初回表示遅延 | < **500ms** （ポーリング1回分） |
| ポーリング1回あたりの CPU 時間 | < **150ms**（typical） |
| `claude agents` 失敗時のフォールバック検出 | < 1秒、UI が壊れない |
| ライブセクション ON/OFF 切替 | 即時（リロード不要） |
| 既存 CSM 機能との競合 | **ゼロ**（既存 PID 生存チェックは Phase 3 までフォールバックとして残す） |

### 1.3 スコープ外（v0.5.0 では扱わない）

- `claude agents` 経由でのバックグラウンドエージェント **起動**（CSM 側からの新規 spawn）
- `claude agents` で kill / pause / resume などの **制御操作**（read-only に徹する）
- 他PC（リモート）の `claude agents` 結果取得
- `claude agents` 出力以外の Claude Code ライブ API（将来 stable API が出たら別途検討）

## 2. アーキテクチャ

### 2.1 `claude agents` コマンド仕様（実機調査結果）

```
$ claude --version
2.1.141 (Claude Code)

$ claude agents --help
Usage: claude agents [options]

Manage background agents

Options:
  --cwd <path>                 Show only background sessions started under <path>
  -h, --help                   Display help for command
  --setting-sources <sources>  Comma-separated list of setting sources to load
                               (user, project, local).
```

**確認できた挙動**:
- 出力は **人間可読テキスト**（`--json` は **無し**）
- `--cwd` で表示を特定パス配下に絞れる
- 非対応環境では `'claude agents' is not available in this environment.` を stderr/stdout に返す（exit code は確認要）
- "background agents" = Task ツール経由で起動された子プロセスを指すと推測

**出力例の確認はランタイムで実施が必要**（実機サーバでは利用不能環境だったため）。プロトタイプ調査タスク T5.1 で：
1. 利用可能環境（Windows / macOS / Linux GUI ターミナル）で複数の実行例を取得
2. running / blocked / done の各状態をサンプル取得
3. 列名・順序・タイムスタンプ形式を確定 → パーサー仕様化

### 2.2 呼び出し方

```typescript
// src/services/claudeAgentsService.ts （新規）
import { exec } from 'node:child_process';
import { promisify } from 'node:util';

const execp = promisify(exec);

export interface ClaudeAgentEntry {
  agentId?: string;          // 取得できれば（パース可否は要調査）
  sessionId?: string;
  status: 'running' | 'blocked' | 'done' | 'unknown';
  cwd: string;
  startedAt?: number;        // ms epoch
  elapsedSec?: number;
  rawLine: string;           // 元行を保持（デバッグ・将来形式変化対策）
}

export async function fetchClaudeAgents(cwd?: string): Promise<ClaudeAgentEntry[]> {
  const args = cwd ? `--cwd ${shellQuote(cwd)}` : '';
  const { stdout, stderr } = await execp(`claude agents ${args}`, {
    timeout: 5000,
    maxBuffer: 1024 * 1024,
  });
  if (/not available in this environment/i.test(stdout + stderr)) {
    throw new ClaudeAgentsUnavailableError();
  }
  return parseClaudeAgentsOutput(stdout);
}
```

**呼び出し形態の選択肢**:

| 選択肢 | 評価 |
|---|---|
| (A) `child_process.exec` でテキスト取得 | ◎ 標準的・実装簡単。**採用** |
| (B) PTY (`node-pty`) | △ TTY 必須な場合のみ。依存増 |
| (C) `claude` の Node API 直接呼び出し | × 公開 API が無い |

### 2.3 ポーリング戦略

**採用**: **タブ可視時のみ 5秒間隔ポーリング**

| 状況 | 動作 |
|---|---|
| エージェントタブが可視 & ライブ機能ON | 5秒ごとに `fetchClaudeAgents` |
| エージェントタブが非可視 | ポーリング **停止** |
| ユーザー操作（refresh ボタン） | 即時取得 |
| 連続失敗 3回 | バックオフ（5s → 30s → 5min） |
| 設定 OFF | 一切呼ばない |

**理由**: イベント駆動（fs.watch / fsEvents）は `claude agents` の内部状態に依存するため信頼性が低い。ポーリングが堅実。

```typescript
// 設定キー
"claudeManager.claudeAgentsIntegration.enabled": true,
"claudeManager.claudeAgentsIntegration.pollingIntervalMs": 5000,
"claudeManager.claudeAgentsIntegration.scopeToWorkspace": true  // --cwd を渡すか
```

### 2.4 データモデル統合

`claude agents` のエントリと CSM 既存 `AgentInfo` をどう紐づけるか：

```
┌─ claude agents 出力 ───────┐
│ sessionId, status, cwd, ... │
└──────────┬──────────────────┘
           │ join by sessionId
           ▼
┌─ CSM AgentInfo（既存） ────┐
│ name, sessionId, role, ...  │
└──────────┬──────────────────┘
           │
           ▼
┌─ ハイブリッド表示モデル ───┐
│ LiveAgentView               │
│   name (CSM由来 or "(unnamed)")
│   status (claude agents由来)
│   sessionId
│   cwd
│   elapsedSec
│   linkedAgent?: AgentInfo   │
└──────────────────────────────┘
```

**マッチング規則**:
1. **`sessionId` 一致** → 確定マッチ → エージェント名を CSM 側から表示
2. **`cwd` 一致 & sessionId 不明** → 推定マッチ（弱）→ "推定: <name>" 表示
3. **マッチなし** → "(未登録セッション)" として独立行表示 → クリックで「エージェント登録」誘導

### 2.5 キャッシュ戦略

| データ | 保持先 | TTL |
|---|---|---|
| 最新の ClaudeAgentEntry[] | メモリのみ | 次回ポーリングまで |
| `claude agents` 可用性（環境チェック） | メモリ | 拡張機能セッション中 |
| マッチング結果（sessionId→agentName） | メモリ | 5分 |

**永続化は不要**（ライブ状態は再起動ごとに変わる）。

### 2.6 全体データフロー

```
[Polling Timer (5s, visibility-aware)]
        │
        ▼
[ClaudeAgentsService.fetch()]
        │ exec("claude agents --cwd <ws>")
        ▼
[Output Parser]
        │
        ▼
[Joiner] ←─── [AgentRegistry (既存)]
        │
        ▼
[LiveAgentView[]]
        │
        ▼
[agentTreeProvider: 「🟢 ライブ状態」セクション]
        │
        ▼ (click)
[既存 previewAgent / openInClaude へ]
```

## 4. 段階導入計画

### Phase 1：ライブ状態セクション追加（read-only） — 1スプリント

**ゴール**: 「🟢 ライブ状態」セクションが見える。クリック動作は無し。

- `ClaudeAgentsService` 新規（fetch + parse + 可用性検出）
- 可用性キャッシュ（環境チェック）
- agentTreeProvider に新セクション追加
- 設定 `enabled` / `pollingIntervalMs` 追加
- 非対応環境のメッセージ表示

**完了条件**: 対応環境で `claude agents` の出力が CSM に表示される。

### Phase 2：クリックアクション統合 — 1スプリント

**ゴール**: ライブ行から既存 CSM 機能へシームレスに遷移。

- 行クリック → `previewSession`（既存）
- ダブルクリック → `openInClaude`（既存）
- 右クリックメニュー（v050-menu-redesign の方針に準拠）
- sessionId マッチング・cwd マッチング実装
- 未登録セッションへの「エージェント登録」誘導

**完了条件**: ライブ状態から CSM のプレビュー／登録フローへ繋がる。

### Phase 3：PID 生存チェック置換 — 1スプリント

**ゴール**: CSM 既存の独自死活監視を `claude agents` 由来データで置換し、コードを簡素化。

- 既存 `usageMonitor` / `agentWatcher` の死活判定箇所を ClaudeAgentsService 由来に切替
- フォールバック：`claude agents` 利用不可時は **既存 PID 生存チェックに自動戻り**
- "live" "idle" バッジを `claude agents` ベースに統一
- 既存実装は削除せず deprecated コメント → v0.6.0 で削除予定

**完了条件**: 同じエージェントの "ライブ" バッジが両方の経路で一致して表示される（A/B 比較期間あり）。

## 5. 互換性・フォールバック

### 5.1 Claude Code バージョン分岐

| バージョン | 動作 |
|---|---|
| < 2.1.139 | `claude agents` コマンド不在 → 起動時に **1回だけ可用性チェック** → セクション自体を非表示 |
| 2.1.139〜2.1.x | `--cwd` のみ利用、`--json` 無し前提でテキストパース |
| 2.2.x 以降 | `--json` 追加されたら自動採用（feature detection） |

### 5.2 実行失敗時のエラーハンドリング

| エラー種別 | 検出方法 | 対応 |
|---|---|---|
| コマンド不在 (ENOENT) | `error.code === 'ENOENT'` | 可用性 false 化 → セクション非表示 |
| 環境非対応 | stdout に `not available in this environment` | 可用性 false 化 → 説明メッセージ |
| タイムアウト (5s) | `error.killed` | 「取得タイムアウト」表示、バックオフ |
| 権限エラー | exit code != 0 + stderr | エラーログに記録、ユーザーに通知（1回のみ） |
| 出力パース失敗 | parser exception | rawLine を保持、未知行として安全表示 |

### 5.3 ユーザー設定で完全無効化

```json
{
  "claudeManager.claudeAgentsIntegration.enabled": false
}
```

→ セクション非表示、ポーリングも一切起こさない。デフォルト `true`、可用性チェック失敗時は自動 `false` 相当の表示。

### 5.4 既存機能との共存

- 既存 `agentWatcher.ts`（PID 生存チェック）は **Phase 3 まで継続稼働**
- 両者の表示が食い違う場合は Phase 3 期間中に A/B 比較ログを採取
- 食い違いが多発したら deprecation を延期

## 6. リスク

| # | リスク | 影響 | 緩和策 |
|---|---|---|---|
| R1 | `claude agents` 出力形式が将来変更される | パース全滅 | rawLine 保持 + 列ヘッダ検出 + 失敗時フォールバック |
| R2 | `claude agents` が experimental 機能で廃止される可能性 | 機能ロスト | Phase 3 の置換を急がず、既存 PID チェックを残す |
| R3 | 5秒ポーリングが遅い PC で重い | UI 体感悪化 | pollingIntervalMs を可変・タブ非可視時停止 |
| R4 | `--json` 無しのテキストパースが脆い | 信頼性低 | `--cwd` で対象を絞る + 行単位の冗長パース + Anthropic Issue 化 |
| R5 | 非対応環境が多くて Phase 1 が役立たず | ユーザー価値低 | 可用性検出を確実に行い、表示メッセージで状況を明示 |
| R6 | TTY 依存の可能性（"is not available in this environment" の意味次第） | exec 経由で動かない | T5.1 調査で原因特定。必要なら `node-pty` 経由（重い）も検討 |
| R7 | 競合機能（agentWatcher）の二重メンテ | 開発負荷 | Phase 3 で deprecated 宣言 |
| R8 | sessionId が出力に含まれない場合 | CSM との join 不能 | cwd ベース推定マッチ + "(未登録)" 表示 |
