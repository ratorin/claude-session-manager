### ⚠ 最重要発見3件

1. **`cliBuilder.ts` の `MODEL_MAP` が `claude-opus-4-6` で固定** — agentFormPanel は「Opus 4.8」ラベルを既に表示しているが、実起動時のモデル指定は 4-6 のまま。**整合性違反・要即修正**
2. **`claude agents --json` が 2.1.145+ で正式 API 化された** — `claudeAgentsService` は JSON 経路に対応済（既に活用中）。残るは旧テキストパース経路の **deprecation 検討**
3. **`/workflows` 機能（2.1.154 以降）に CSM は未対応** — ライブ状態に表示されるエージェントが workflow 由来か単独 IDE 起動かを区別できない

## 4. アーキテクチャ観点の指摘

### 4.1 整合性違反パターン

- **論理モデル名 → 物理モデル名の翻訳が `cliBuilder.ts` 1ヶ所に集中している** にもかかわらず、UI ラベル（agentFormPanel）と乖離している。
- 推奨：`data/model-aliases.json` を新規追加し、`{ "opus": { "current": "claude-opus-4-8", "ui": "Opus 4.8", "deprecated": ["claude-opus-4-6","claude-opus-4-7"] } }` 形式で **単一情報源化**。バージョン追従が容易になる。

### 4.2 機能境界の曖昧さ

- `agentWatcher`（死活監視）と `claudeAgentsService`（ライブ状態）の責務が重複。
- 推奨：v0.5.0 設計書の Phase 3 を実行 → agentWatcher は **fallback only**（claude agents 非対応環境）。

### 4.3 設定の散在

`claudeManager.*` 設定キーが現在 20以上。3カテゴリに整理推奨：
- `claudeManager.ui.*`（タブ/locale/show5d 等）
- `claudeManager.live.*`（claudeAgentsIntegration / usageMonitor 統合）
- `claudeManager.agents.*`（既存）

## 6. 結論

CSM v0.5.x は **23 カテゴリ中 16 が ◎/○ で健全**。緊急対応が必要なのは **2件のみ（Opus 4.8 起動マッピング・workflow kind 判別）**。

主要な「次の一手」は3つ：

1. **P0：cliBuilder の MODEL_MAP を Opus 4.8 へ即更新**（UIラベルと実起動が食い違う重大不整合）

3. **P3：動的ワークフロー統合**（→ `v0.5.x-workflows-integration.md` 参照）
