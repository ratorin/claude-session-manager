## 12部署のAIエージェントを同時に走らせている

Claude Codeで開発していると、セッションが溜まる。1日に20〜30本。どれがどのタスクだったか、どのエージェントに何を頼んだか、1週間後にはわからなくなる。

自分の場合はさらに極端で、「取締役」と呼ぶOpusセッションが全体を統括し、その下にCSM開発部、品質管理部、資料作成部など12の部署（子エージェント）がぶら下がっている。取締役がタスクを分割して各部署に投げ、品質管理部がコードレビューし、資料作成部がドキュメントを整備する。

この運用を支えるために作ったのが **Claude Session Manager**（以下CSM）だ。

[スクリーンショット: VS Codeサイドバーに表示されたCSMの会話一覧・エージェント管理・メモリ管理の3ペイン]

## CSMとは

Claude Codeの会話履歴・メモリ・エージェントを管理するVS Code拡張機能。Claude Code本体にないセッション管理機能を補完する。

```
機能一覧:
├── 会話管理（一覧・検索・ブックマーク・タグ・メモ・プレビュー）
├── メモリ管理（一覧・編集・統合・抽出・容量表示）
├── エージェント管理（登録・組織図・ステータス監視）
├── タスク管理（状態自動追跡・通知・ログ）
└── 利用制限モニター（5h/7d利用率表示）
```

VS Code Marketplaceからインストールできる。

```
ext install ratorin.claude-session-manager
```

動作要件はVS Code 1.85以上とClaude Code拡張機能のみ。

## セッション管理 — 本来のメイン機能

CSMのコアはセッション管理だ。`~/.claude/projects/` 配下のJSONLファイルを解析し、全プロジェクトの会話を一覧表示する。

### 日付別自動分類

今日 / 昨日 / 今週 / 今月 / それ以前に自動分類。ソートは7種（更新日・作成日・名前・件数・モデル）、グループは4種（日付・タグ・エージェント・フラット）。

### ブックマーク・タグ・メモ

重要な会話はブックマークで即アクセス。タグで「バグ修正」「設計」「調査」とカテゴリ分け。メモ欄にはセッションの目的や結論を残せる（500ms遅延で自動保存）。

地味だが、1ヶ月前の会話を探すときにこれがないと詰む。

### Markdownプレビュー

会話内容をチャット形式でプレビュー表示する。コードブロック、テーブル、見出し、リストをMarkdownレンダリング。プレビュー内のURLはブラウザで、ファイルパスはエディタで直接開ける（行番号ジャンプ付き）。

[スクリーンショット: 会話プレビューパネル。コードブロックとテーブルがレンダリングされている様子]

### ライブセッション検出

現在Claude Codeが使用中のセッションを緑の●で表示。PID生存チェックでゾンビセッションも自動判別する。

### 子エージェントのツリー表示

Claude CodeのAgent toolが生成する `subagents/` フォルダ内のJSONLを自動検出し、親セッションの子ノードとしてツリー表示する。タイプ別アイコン付き（🔍Explore / 📋Plan / 🔧汎用 / 📖ガイド）。

## メモリ管理

Claude Codeのメモリファイル（`~/.claude/projects/*/memory/`）をツリー表示。タイプ別バッジ（user / feedback / project / reference）で視認性を確保。

- インデックス使用率をインジケーターバーで表示（MEMORY.mdの最大200行に対する使用量）
- プレビュー・編集・統合・抽出・削除がGUIで完結
- `settings.json` / `settings.local.json` もツリーのトップに表示してワンクリックで編集

[スクリーンショット: メモリ管理ツリー。タイプ別バッジとインジケーターバーが見える状態]

## エージェント管理 — CSMのユニークポイント

ここからがCSMの本領。セッションを「エージェント」として登録し、組織構造で管理する。

### 登録フロー

1. 会話一覧でセッションを右クリック →「エージェントとして登録」
2. Webviewフォームで設定を入力

| 項目 | 内容 |
|------|------|
| 部署名 | エージェントの識別名（例: CSM開発部） |
| 役割 | 担当業務のテキスト |
| モデル | opus / sonnet / haiku（カード型ラジオで選択） |
| セッション運用 | 固定（同じセッションを継続）/ 使い捨て |
| スコープ | プロジェクト / グローバル |
| 親エージェント | 上司を選択 → 組織図に階層表示 |
| 推論努力（Effort） | Low / Medium / High / Max |
| Extended Thinking | ON / OFF |

登録すると **ルールファイル**（.md）が自動生成される。これがエージェントの行動規範になる。セッションが変わってもルールファイルは残るので、**長期記憶**として機能する。

[スクリーンショット: エージェント登録フォーム。カード型ラジオボタンでモデル・スコープを選択している様子]

### 組織図

ステータスバーをクリックすると、登録済みエージェントの組織図がWebviewパネルで開く。各カードにモデルバッジ・役割・セッション状態を表示。カードから直接Claude Codeでセッションを開いたり、会話履歴をプレビューしたりできる。

[スクリーンショット: 組織図パネル。取締役→各部署のツリー構造がカード表示されている]

### タスク管理

v0.3.0で追加。エージェントにタスクを割り当てると、状態を自動追跡する。

- **running** — PID生存 + セッションファイルが更新中
- **stalled** — 60秒以上更新がない（閾値は設定可能）
- **completed** / **error** — 完了またはエラー

タスク完了・エラー・応答停止をVS Code通知でリアルタイムに知らせてくれる。エージェントツリーの子ノードとしてタスクログが表示され、経過時間とステータスアイコンで一目で状況がわかる。

### セッションの引き継ぎ

コンテキストウィンドウの上限に達したら「セッションを新しくする」を使う。

2つのモードがある:
- **簡易（即時）** — JSONL末尾から自動抽出した要約を生成
- **詳細（AI要約）** — Claude CLIを呼び出して高品質な要約を生成

生成された遺言はルールファイルの「歴代セッションの記録」セクションに自動蓄積される（直近3世代保持）。新セッションはルールファイル経由で過去の経緯を自動的に把握するので、引き継ぎのコンテキストロスが最小限に抑えられる。

### 利用制限モニター

Anthropic APIから5時間/7日の利用率を取得してステータスバーに表示。80%超で警告色、95%超でエラー色、90%/100%到達で通知。デフォルトOFF（有効化しても月額$0.01未満の軽量リクエスト）。

## 実際の運用例: 12部署体制

自分が実際に運用している構成を紹介する。

```
取締役（Opus・固定）— 全体統括・タスク分割・最終判断
  ├── CSM開発部（Sonnet・固定）— CSMの機能実装
  ├── AL開発部（Sonnet・固定）— 別プロジェクトの開発
  │     └── ALデバッグ班（Sonnet・使い捨て）
  ├── 品質管理部（Sonnet・使い捨て）— コードレビュー・仕様整合チェック
  ├── 資料作成部（Sonnet・使い捨て）— ドキュメント・手順書
  ├── テスト部（Sonnet・使い捨て）— テスト設計・実行
  ├── 調査部（Sonnet・使い捨て）— 技術調査・情報収集
  ├── サーバー管理部（Sonnet・使い捨て）— インフラ・デプロイ
  └── 総務部（Haiku・使い捨て）— 定型作業・雑務
```

### 運用のコツ

**取締役はOpus・固定セッション**にする。全体を見渡す判断力が必要で、文脈を長期保持したいから。固定セッションはルールファイルに経験が蓄積されるので、使い込むほど賢くなる。

**品質管理部は使い捨て**にする。毎回フレッシュな目でレビューしたほうが、馴れ合いにならず品質が上がる。実際、品質管理部がSPEC.mdの古い仕様記述を14箇所指摘してくれた。

**モデルの使い分けでコストを最適化**する。取締役やコア開発はOpus/Sonnet、定型作業はHaikuで十分。CSMのフォームでモデルを選ぶだけで、Extended ThinkingやEffortも連動してグレーアウトが切り替わる。

### 品質管理フロー

CSM開発部がコードを書く → 品質管理部がレビュー → 指摘を修正 → 再レビュー。このサイクルをCSMのタスク管理で回している。

品質管理部のレビューは、セッションIDを指定して「このセッションのSPEC.mdをレビューして」と依頼する。CSMの「セッションパスをコピー」機能で、JNOLファイルのフルパスを渡せるので、別エージェントが直接読める。

## claude-squad との比較

Claude Codeのマルチエージェントツールとしては [claude-squad](https://github.com/smtg-ai/claude-squad) が知られている。

| | CSM | claude-squad |
|---|---|---|
| アプローチ | **組織管理**（登録・役割・階層） | **プロセス管理**（tmux並列実行） |
| 実行方式 | VS Code拡張 | CLIツール |
| セッション管理 | 履歴・検索・ブックマーク・タグ | tmuxセッションの並列表示 |
| エージェント定義 | 部署名・役割・モデル・ルールファイル | コマンドライン引数 |
| 組織構造 | 親子階層・組織図表示 | フラット |
| 永続性 | ルールファイルで長期記憶 | セッション単位 |
| 状態監視 | タスク追跡・通知・自動クリーンアップ | tmuxペインの目視 |
| メモリ管理 | 統合・抽出・容量表示 | なし |
| 対象 | VS Codeユーザー | ターミナルユーザー |

一言でまとめると:

- **claude-squad** = 「AIを並列で走らせるツール」
- **CSM** = 「AIの組織を作って管理するツール」

claude-squadは複数のClaude Codeインスタンスをtmuxで並列実行するのに長けている。CSMはセッションの蓄積・検索・エージェントの役割定義・引き継ぎ・品質管理フローなど、**継続的な運用**に重点を置いている。

併用も可能で、実行はclaude-squad、管理はCSMという使い分けもありだと思う。

## 設定項目（抜粋）

VS Codeの設定（`Ctrl+,`）から `claudeManager` で検索。

| 設定 | デフォルト | 説明 |
|------|-----------|------|
| `enableAgentMonitor` | false | リアルタイム監視ON/OFF |
| `agentMonitorInterval` | 5秒 | 監視間隔 |
| `enableNotifications` | true | タスク通知ON/OFF |
| `taskStalledThreshold` | 60秒 | 応答停止の判定閾値 |
| `enableUsageMonitor` | false | 利用制限モニターON/OFF |
| `maxSessionsShown` | 500 | 表示するセッション最大数 |
| `preview.showThinkingBlocks` | false | AIの思考過程を表示 |

全15項目。詳細はREADMEの設定セクション参照。

## インストールと始め方

```bash
# VS Code Marketplaceからインストール
ext install ratorin.claude-session-manager
```

1. VS Code左のアクティビティバーに💬アイコンが出る
2. 「エージェント管理」のウェルカム画面で「取締役を登録」をクリック
3. 取締役プリセット（Opus・固定・全体統括）で即座に開始
4. セッション一覧から右クリック →「エージェントとして登録」で部署を追加

エージェント1人から始めて、必要に応じて増やしていくのがおすすめ。最初から12部署作る必要はない。

現在v0.3.0。直近で検討しているのは:

## まとめ

Claude Codeのセッション管理は、会話が増えるほど破綻する。CSMはその問題を「セッションに名前・タグ・ブックマーク・メモをつけて整理する」というシンプルなアプローチで解決する。

エージェント管理はその延長線上にある。セッションに役割を持たせ、階層構造にし、ルールファイルで行動規範を定義する。会話が終わっても記憶は残り、引き継ぎで途切れない。

1人のClaude Codeを便利に使うだけなら、セッション管理機能だけで十分価値がある。複数エージェントを組織的に動かしたくなったら、エージェント管理を試してみてほしい。
