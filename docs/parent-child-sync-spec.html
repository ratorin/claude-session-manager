1. 背景と課題

現在のCSMでは、エージェント間の親子関係は session-manager.json の parentAgent フィールドで管理されている。しかし、子エージェントを追加しても親のルールファイルには子の情報が反映されない。

具体的な問題
  • 親エージェント（例: 取締役）は、配下にどの子エージェントがいるかルールファイルから知ることができない
  • Claude Codeはセッション開始時にルールファイルを読むため、子の存在を知らないまま動作する
  • 結果、タスク委任ができず、全てを自分で処理してしまう
  • 手動でルールファイルに子エージェント情報を書いても、子の追加・削除・変更時に同期が壊れる

2. 設計概要

方針: マーカーセクション方式

親のルールファイル本文（YAMLフロントマター以降）に、HTMLコメントマーカーで囲んだ自動管理セクションを設ける。このセクション内のみCSMが自動更新し、マーカー外の手動記述は一切触れない。

設計判断: なぜフロントマターではなく本文か？
  • フロントマターの description はClaude Codeのsystem promptに注入される重要な領域。ここに子リストを入れると肥大化する
  • 本文はユーザーが自由にカスタマイズできる領域であり、マーカーで区切ることでCSM管理部分と共存できる
  • 既存の buildDescription() テンプレートとの干渉を避けられる

3.3 子が0件の場合

子エージェントが全て削除された場合、セクション自体を削除する（マーカーも含めて完全除去）。空のセクションを残さない。

3.4 挿入位置

挿入位置の決定ロジック（優先順）
  1. 既にマーカーが存在する場合 → マーカー間を置換
  2. 本文末尾に追加（改行2つ + マーカーセクション）

4. トリガーイベント

イベント トリガー箇所 同期内容
子エージェント追加 addAgent() 完了後 新しい親のルールファイルに子を追記
子エージェント削除 removeAgent() 完了後 親のルールファイルから該当行を削除。子が0件になったらセクション除去
子の名前変更 onSave（名前変更検出時） 旧名で removeAgent → 新名で addAgent → 親を1回同期
子のモデル変更 onSave（編集時） 親のテーブル行を更新
子の役割変更 onSave（編集時） 親のテーブル行を更新
親変更（移動） onSave（parentAgent変更検出時） 旧親から削除 + 新親に追加
一括再生成 手動コマンド 全ての親ルールファイルを再生成（リペア用）

5.2 名前変更時のフロー レビュー指摘対応

背景: extension.ts の名前変更処理は removeAgent(oldName) → addAgent(newConfig) の2ステップ。同期は addAgent 完了後の1回で十分（syncParentRuleFile は子一覧を再取得してセクション全体を再生成するため）。
■ 子エージェント名前変更 extension.ts: onSave(newConfig), oldName !== newConfig.name → dataStore.removeAgent(oldName) // 旧名を削除 → autoGenerateRuleFile(newConfig) // 子のルールファイル更新 → dataStore.addAgent(newConfig) // 新名で保存 → syncParentRuleFile(newConfig.parentAgent) // ★1回の同期で旧名行が消え新名行が入る

5.3 セクション生成ロジック レビュー指摘対応

// Markdownテーブルのセル値をエスケープ（パイプ・改行）
function escapeTableCell(value: string): string {
    return value.replace(/\|/g, '\\|').replace(/\n/g, ' ');
}

function buildChildrenSection(children: AgentConfig[]): string {
    if (children.length === 0) return '';  // セクション自体を生成しない

    const header = '<!-- CSM:CHILDREN:START -->\n## 配下エージェント\n';
    const tableHeader = '| 部署名 | モデル | 役割 | セッションモード |\n|--------|--------|------|------------------|\n';

    const rows = children
        .sort((a, b) => a.name.localeCompare(b.name, 'ja'))
        .map(c => {
            const name = escapeTableCell(c.name);        // ★全フィールドをエスケープ
            const model = escapeTableCell(c.model);
            const mode = c.sessionMode === 'disposable' ? '使い捨て' : '固定';
            const role = escapeTableCell(c.role || '未設定');
            return `| ${name} | ${model} | ${role} | ${mode} |`;
        })
        .join('\n');

    const footer = '\n\n必要に応じて上記エージェントにタスクを委任してください。\n<!-- CSM:CHILDREN:END -->';

    return header + tableHeader + rows + footer;
}

5.4 マーカー検証・置換ロジック レビュー指摘対応

マーカー破損チェックは replaceChildrenSection 内部で統一的に行う。

type MarkerState = 'valid' | 'corrupted' | 'absent';

interface ReplaceResult {
    content: string;
    state: MarkerState;
}

function replaceChildrenSection(content: string, newSection: string): ReplaceResult {
    const startMarker = '<!-- CSM:CHILDREN:START -->';
    const endMarker = '<!-- CSM:CHILDREN:END -->';

    const startIdx = content.indexOf(startMarker);
    const endIdx = content.indexOf(endMarker);

    // マーカー破損チェック（片方のみ存在）
    if ((startIdx !== -1) !== (endIdx !== -1)) {
        return { content, state: 'corrupted' };
    }
    // 開始が終了より後ろ（逆順）
    if (startIdx !== -1 && startIdx > endIdx) {
        return { content, state: 'corrupted' };
    }

    if (startIdx !== -1 && endIdx !== -1) {
        // マーカー間を置換
        const before = content.substring(0, startIdx);
        const after = content.substring(endIdx + endMarker.length);

        if (newSection === '') {
            // 子が0件: セクションごと削除
            // before末尾とafter先頭の空行を1つの改行に正規化
            const trimmedBefore = before.replace(/\n{2,}$/, '\n');
            const trimmedAfter = after.replace(/^\n{2,}/, '\n');
            return {
                content: trimmedBefore + trimmedAfter,
                state: 'valid'
            };
        }
        return { content: before + newSection + after, state: 'valid' };
    }

    // マーカーなし
    if (newSection === '') return { content, state: 'absent' };  // 追加不要
    return {
        content: content.trimEnd() + '\n\n' + newSection + '\n',
        state: 'absent'
    };
}

5.5 クロススコープ親子関係ポリシー レビュー指摘対応

スコープをまたいだ親子関係の扱い

dataStore.getAgents() はグローバル+ローカルのマージ済みリストを返す（ローカル優先）。syncParentRuleFile は常にこのマージ済みリストを使用する。

親のスコープ 子のスコープ 同期可否 理由
グローバル グローバル ○ 同期する 同一スコープ、問題なし
グローバル ローカル ○ 同期する グローバル親のルールファイルにローカル子の情報を追記。他プロジェクトでは不可視だが、CSMの子一覧は動的に再生成されるため問題なし
ローカル グローバル ○ 同期する ローカル親のルールファイルにグローバル子の情報を追記
ローカル ローカル ○ 同期する 同一スコープ、問題なし

方針: スコープに関わらず全て同期する。syncParentRuleFile は子一覧を毎回 getAgents() から取得して全体を再生成するため、スコープの差異は自動的に解消される。

5.6 親変更時のフロー（子の parentAgent が変更された場合）

editAgent 検出: oldParent !== newParent │ ├── syncParentRuleFile(oldParent) ← 旧親から削除 │ └── syncParentRuleFile(newParent) ← 新親に追加

6. 循環参照防止

CRITICAL: 循環参照は無限ループやデータ破損を引き起こす可能性がある。エージェント追加・編集時に必ず検証すること。

6.1 検証ロジック レビュー指摘対応

関数名を hasCircularRef に変更（返り値の意味を直感的に）。

/**
 * 循環参照を検出する。
 * childName を parentName の子として設定する場合に、
 * parentName の祖先チェーンに childName が含まれていないか検証。
 *
 * @returns true = 循環あり（設定不可）, false = 安全（設定可能）
 */
function hasCircularRef(
    childName: string,
    parentName: string,
    agents: AgentConfig[]
): boolean {
    const agentMap = new Map(agents.map(a => [a.name, a]));
    const visited = new Set<string>();
    let current = parentName;

    while (current) {
        if (current === childName) return true;  // 循環検出
        if (visited.has(current)) return true;    // 既訪問（別の循環）
        visited.add(current);
        const agent = agentMap.get(current);
        current = agent?.parentAgent || '';
    }
    return false;
}

7. カスタム部分の保護

7.1 保護原則

絶対に変更しない領域
  1. YAMLフロントマター — updateFrontmatterInContent() の管轄。本機能は触れない
  2. マーカー外の本文 — ユーザーが手動で書いた全ての記述

7.2 保護メカニズム レビュー指摘対応

  • マーカー検索は indexOf() で正確にマッチ
  • マーカー破損チェックは replaceChildrenSection() 内部で統一（返り値の state で呼び出し元に通知）
  • マーカー内にユーザーが手動で追記した内容は上書きされる（マーカー内はCSM管理領域であることをコメントで明記）
  • 2重マーカー問題: indexOf() は最初のマーカーペアを検出。2つ目以降のマーカーが存在する場合は無視される。テストケースで検証する

7.3 破損時の処理

// replaceChildrenSection が 'corrupted' を返した場合
const result = replaceChildrenSection(content, newSection);
if (result.state === 'corrupted') {
    outputChannel.appendLine(
        `[WARN] ${parentName} のルールファイルでCHILDRENマーカーが破損しています。` +
        `手動で修正するか、一括再生成コマンドを実行してください。`
    );
    return;  // 変更しない
}

12. マイグレーション レビュー指摘対応

12.1 既存環境への導入

既存のルールファイルにはCHILDRENマーカーが存在しない。以下の方式で対応:

方式: マーカー不在時の毎回同期

syncParentRuleFile は「マーカーなし + 子あり → 末尾に追加」の動作をする。つまり、エージェント操作のたびに自動的にマーカーが追加される。特別なマイグレーション処理は不要。

  • 子エージェントを追加・編集すれば、その時点で親にマーカーが入る
  • 既存環境を一気に全て更新したい場合は claudeManager.syncAllParentRules コマンドを手動実行
  • ユーザーがマーカーを手動削除した場合: 次回のエージェント操作で再追加される（意図的な動作）
activate()時の自動実行は行わない。 理由: 起動のたびに全ルールファイルを走査するのはパフォーマンスに影響する。ユーザーが必要と判断した場合に手動コマンドで実行する。

12.2 手動記述との共存

既に手動で子エージェント情報を書いているユーザーがいる可能性がある。マーカー追加時に既存の手動記述はそのまま残す（マーカー外なので影響しない）。ユーザーが手動記述を不要と判断したら自分で削除してもらう。

13. リスクと対策

リスク 深刻度 対策
ルールファイルのカスタム記述を上書き CRITICAL マーカー内のみ操作。マーカー外は一切触れない。破損時は変更しない
循環参照による無限ループ CRITICAL hasCircularRef() でフォーム送信時 + 保存時の二重チェック
同時編集によるファイル競合 HIGH 親名単位のasync mutex排他制御（下記実装参照）
大量の子エージェントでセクションが肥大化 LOW テーブル形式で1行1エージェント。20件程度なら問題なし
ルールファイルがUTF-8以外 LOW CSMは全てUTF-8前提。他エンコーディングは非対応

排他制御の実装方針 レビュー指摘対応

// 親名ごとにロックを管理（同じ親への同時書き込み防止）
// ★解決済みPromiseは自動クリーンアップ（メモリリーク対策）
const syncLocks = new Map<string, Promise<void>>();

async function syncParentRuleFile(parentName: string): Promise<void> {
    if (!parentName) return;

    // 前回の同期が完了するまで待つ
    const prev = syncLocks.get(parentName) || Promise.resolve();
    const current = prev
        .then(() => doSync(parentName))
        .catch((err) => {
            // エラーをOutputChannelに出力（飲み込まない）
            outputChannel.appendLine(
                `[ERROR] ${parentName} の親ルール同期に失敗: ${err.message}`
            );
        })
        .finally(() => {
            // ★完了後にMapから削除（メモリリーク防止）
            if (syncLocks.get(parentName) === current) {
                syncLocks.delete(parentName);
            }
        });
    syncLocks.set(parentName, current);
    await current;
}

// syncAllParentRuleFiles は逐次実行（同一ファイルへの並行書き込み防止）
async function syncAllParentRuleFiles(): Promise<void> {
    const agents = await dataStore.getAgents();
    const parentNames = new Set(
        agents.filter(a => a.parentAgent).map(a => a.parentAgent!)
    );
    for (const parentName of parentNames) {
        await syncParentRuleFile(parentName);  // 逐次実行
    }
}
