★v0.4.2〜v0.4.4 新機能ハイライト

CSM を v0.4.1 以前から更新した方向けに、この1年の主要な変更点を先にまとめます。

v0.4.2 で追加

🪟 エージェントプレビューパネル

サイドバーでエージェントをクリックすると、配下ツリー・連携先・TODO / HISTORY を1画面で確認できる Webview が開きます。設定編集ボタン・ルールファイル編集ボタンもヘッダに配置。

📋 確認待ち横断ビュー

全エージェントの未完了 TODO を1つのビューで横断表示。チェックを付けると各 TODO.md に即時反映され、抜け漏れを一元管理できます。

💬 /csm-ask-agent スキル

旧 /ask-agent からリネーム。Claude セッション内で /csm-ask-agent <エージェント名> "指示" と書くと、バックグラウンドで起動し完了時に結果を報告します。

🧠 SessionStart hook で役割自動注入

CSM が紐づけたエージェント定義（YAMLフロントマター＋本文）を、セッション開始時に自動でコンテキストへ読み込み。--append-system-prompt-file の指定忘れがなくなります。

🛡 ガバナンス記録

Bash / Edit / Write 操作で秘密鍵や危険コマンドを検知し、~/.claude/governance-events.jsonl に記録します。事故の痕跡を後から追跡可能。

📝 PreCompact hook

コンパクション前に CSM_SUMMARY を自動生成し、HISTORY.md に記録。作業履歴がセッション跨ぎでも失われません。

🏗 extension.ts を分割

2,776 行 → 347 行に圧縮し、services/ と commands/ に機能別分離。保守性が大幅に向上。

v0.4.3 で追加

🪟 Windows .cmd EINVAL 回避

Node.js CVE-2024-27980 対応。claude.cmd ラッパーを経由せず、cli.js を node で直接起動することで起動失敗を解消。

🔗 他プロジェクトのセッションタイトル解決

グローバルエージェントを別ワークスペースから見てもセッションタイトルが正しく表示されるようになりました。

📁 workDir への自動 cd

/csm-ask-agent の --resume がセッション作成時と同じ cwd で動くよう、エージェントの workDir に自動で cd します。

🩹 空 sessionId 自動クリーンアップ

起動時のマイグレーションで、壊れた紐づけ（空 sessionId）を自動修復します。

v0.4.4 で追加

⚡ Claude Code v2.1.113 対応

claude.exe ネイティブバイナリを優先起動。見つからない場合は cli.js にフォールバックするため、旧環境でも動作します。

🗂 「Claude で開く（IDE）」ワークスペース整合チェック

セッション作成時の cwd と現 VS Code ワークスペースの不一致を検出し、「そのフォルダを開く／ワークスペースに追加／このまま開く」の3択を提示。意図しないフォルダで再開する事故を防止。

⏱ サブエージェント 10 分タイムアウト対応

Claude Code v2.1.113+ の仕様に合わせ、taskErrorThreshold（既定 30 分）を追加。stalled が長時間続くと自動で error に昇格します。

🐞 エラー自動収集＆不具合報告

unhandledRejection / uncaughtException を ~/.claude/csm-errors.log に記録。コマンド「不具合を報告（GitHub Issue 作成）」で、本文にエラーサマリーを添えた Issue URL が自動生成されます。

🔗 新規登録後に紐づけピッカーへ誘導

v0.4.3 までの「自動セッション作成」は廃止。登録直後に既存セッションの紐づけピッカーが開き、ユーザーが明示的に選択します。

🆚 IDE / ターミナルの使い分けを整理

グローバル＋使い捨てエージェントはターミナル向け、プロジェクト＋固定セッションはIDE向け、とコマンドメニューも整理されました。

詳細は：各機能の詳細は後続のセクションで触れています。特にセクション 6（エージェント管理）・セクション 11（運用ガイド）・セクション ⓣ（トラブルシューティング）に最新情報がまとまっています。

6エージェント管理

Claude Code CLI標準の ~/.claude/agents/*.md をSingle Source of Truthとして、エージェント（部署）を管理します。
v0.4.0でCLIネイティブの --agent 方式に完全移行しました。

仕組み：エージェント定義は ~/.claude/agents/*.md のYAMLフロントマターに書かれます。CSMはこのファイルを読み取ってサイドバー・組織図・プレビューに表示します。session-manager.json にはブックマーク・タグ・セッション紐づけ情報のみ保存されます。

エージェント定義ファイルの構造

~/.claude/agents/csm-dev.md
---
name: CSM開発部
description: CSM拡張機能の開発
model: sonnet
memory: project
tools: ["Read", "Edit", "Write", "Bash"]
permissionMode: default

parentAgent: director  ← 組織図の親子関係
status: active
workDir: c:/xampp/Project/csm
---
（本文 = システムプロンプト）

エージェント設定項目

名前・役割（CLI標準）

例: 「CSM開発部」「テスト担当」。name / description フィールド。

モデル（CLI標準）

model フィールド。選択肢：

  • opus — Claude Opus 4.6
  • sonnet — Claude Sonnet 4.6
  • haiku — Claude Haiku 4.5
  • claude-sonnet-4-6[1m] — Sonnet 4.6（1Mコンテキスト）
  • claude-opus-4-6[1m] — Opus 4.6（1Mコンテキスト）
  • inherit — 親セッションのモデルを継承

⚠️ sonnet[1m] は使わないこと（Sonnet 4.5 旧版になるため）。1M使用時はフル IDで指定。

ツール・権限（CLI標準）

tools（利用可能ツール）、permissionMode（権限モード）、memory（記憶モード）をフロントマターで設定。

親エージェント（CSM独自）

parentAgent フィールドで上位エージェントを設定。組織図でツリー表示される。

作業ディレクトリ（CSM独自）

workDir フィールドでエージェントの作業フォルダを指定。

稼働状態（CSM独自）

status フィールドで active / idle / archived を管理。

プレビューパネル（v0.4.2〜）

サイドバーのエージェントをクリックすると、独立したWebviewパネルでエージェント情報の総合ビューが開きます。

ヘッダー操作

「設定を編集」「ルールファイルを開く」「セッションを開く」「紐づけ」「新セッション」等のボタンをパネル上部に集約。

子エージェントツリー

parentAgent で紐づいた子エージェントを階層表示。クリックで各子のプレビューに遷移。

連携エージェント一覧

/csm-ask-agent で連携可能な他エージェントを一覧表示。横方向の依頼もここから確認。

TODO / HISTORY トグル

ステップ1: 取締役を登録する

取締役の役割

全体統括・タスク分割・最終判断を担う最上位エージェント。ユーザーからの指示を受け取り、各部署に割り振る。

推奨設定

モデル: Opus（高度な判断に対応）
記憶: memory: project（セッション跨ぎで記憶保持）

ステップ2: 部署（子エージェント）を追加する

業務内容に応じて部署を追加します。parentAgent に「director」を設定することで、組織図にツリー表示されます。

モデルの使い分け: 重要な判断・設計 → opus / 通常の開発・調査 → sonnet / 定型・軽量タスク → haiku（コスト効率◎）。大規模文脈が必要な場合は claude-sonnet-4-6[1m] / claude-opus-4-6[1m]（1Mコンテキスト）も利用可能

ステップ3: エージェントを起動する

v0.4.2以降、エージェントへの指示は /csm-ask-agent スキルが推奨です。Claudeセッション内で /csm-ask-agent <エージェント名> "指示内容" と書くと、バックグラウンドでエージェントを起動し完了時に結果を報告します。

# Claude セッション内で推奨（v0.4.2〜）
/csm-ask-agent csm-dev "指示内容"
# 横方向の連携も可能（親子関係不要）
/csm-ask-agent qa "このコードをレビューして"
# 独立した並列タスクは複数回呼ぶ
/csm-ask-agent csm-dev "タスクA"
/csm-ask-agent csm-dev "タスクB"
# 代替（bash・報告の手動確認が必要）
echo "指示内容" | claude --agent csm-dev -p
/csm-ask-agent の特徴： 既存セッションに --resume で自動継続し、結果は c:/xampp/.agent-rules/tmp/agent_{name}_{タスク名}.txt に出力されます。完了報告が自動で返るため能動的に確認する必要がありません。エージェント一覧は python c:/xampp/.claude/scripts/csm-ask-agent.py --list で確認できます。
禁止事項：claude -p 単体（--agent なし）は禁止です（ルール・メモリが適用されず意図しない動作をします）。--continue は禁止です（最新セッションを再開するため、別エージェントのセッションが割り込みます）。Agent ツール（subagent_type）は使い捨て調査のみに使用してください（Issue #14118: 親コンテキスト漏洩バグ）。

ステップ4: ルール（システムプロンプト）を育てる

各 agents/*.md の本文がそのままシステムプロンプトになります。役割・禁止事項・ノウハウを蓄積します。

本文に書くこと

  • エージェントの役割と担当範囲
  • 禁止事項（例: rm禁止 → .trash/に移動）
  • 出力形式・言語の指定
  • 部下一覧と /dispatch の使い方

育成のコツ

  • 作業中のフィードバックをその都度追記
  • 「毎回同じ指示」をルール化して省力化
  • memory: project で記憶も自動蓄積
編集方法: エージェントを右クリック → 「定義ファイルを編集」でエディタが開きます。フロントマター（設定部分）と本文（システムプロンプト）の両方を直接編集できます。

16CLI と IDE の使い分け（v0.4.4）

v0.4.4 では、エージェントの性質に応じてターミナル起動とVS Code IDE 起動を自動で切り替えます。「エージェントを開く」実行時にCSMが判定し、最適な方を選びます。

🖥 ターミナル起動（CLI）

対象：グローバルスコープ かつ 使い捨て（workDir 未設定）。

  • 軽量・短命なタスク（調査・ワンショット指示）
  • プロジェクトに縛られない汎用エージェント
  • コマンド: Open in Terminal

🧩 VS Code IDE 起動

対象：プロジェクトスコープ かつ workDir 固定のエージェント。

  • 継続的な開発・編集が必要なエージェント
  • VS Code のワークスペースを自動でそのフォルダに切替
  • コマンド: Open with Claude (IDE)

⚙️ ワークスペース整合性チェック

IDE起動時、現在のワークスペースとエージェントの workDir が一致しない場合、3択ダイアログを表示：

  • 新しいウィンドウで開く
  • 現在のウィンドウで開き直す
  • キャンセル

🚀 Claude Code v2.1.113 対応

ネイティブバイナリ（claude.exe）を優先。見つからない場合は cli.js を node 経由で実行し、Windows の .cmd EINVAL 問題（Node CVE-2024-27980）を回避します。

⏱ subagent 10分タイムアウト対策

Claude Code v2.1.113 以降、subagent 呼び出しは10分で強制終了。CSMはエージェントの taskErrorThreshold（既定30分）を超えたタスクをエラー候補としてマークし、バグ報告に活用できます。

📋 コマンドメニュー整理

コマンドパレットで「CSM:」と入力すると、以下がグループ表示されます：

  • セッション操作（開く・紐づけ・新規）
  • エージェント操作（登録・編集・削除）
  • IDE操作（Open with Claude (IDE)）
  • レポート（Report Bug・確認待ち一覧）
判定ロジック：scope: global かつ workDir 未設定 → ターミナル。scope: project または workDir 指定あり → IDE。/csm-ask-agent 経由の指示は常にバックグラウンドの -p モードで動作し、この分岐とは独立です。
17トラブルシューティング

v0.4.4 で追加されたエラー自動収集とGitHub Issue 作成コマンドにより、不具合の報告が簡単になりました。

よくある問題

❌ セッションが作成されない

症状：エージェントを起動してもセッションが紐づかない。

原因・対処：

  • v0.4.4 以降、自動セッション作成は廃止。エージェント新規作成後に表示される紐づけピッカーで既存セッションを選ぶか、/csm-ask-agent で起動してください。
  • 空の sessionId はマイグレーション時に自動削除されます。

❌ IDE パネルが開かない

症状：「Open with Claude (IDE)」を実行してもVS Codeのパネルが立ち上がらない。

原因・対処：

  • workDir がワークスペースと一致しない → 3択ダイアログで「新しいウィンドウで開く」を選択。
  • claude.exe が見つからない → PATH を確認。CSMは自動で cli.js フォールバックを試みます。
  • Claude Code 拡張機能（anthropic.claude-code）が未インストール。

❌ subagent が10分で止まる

症状：/csm-ask-agent で投げたタスクが途中で終了。

原因・対処：

  • Claude Code v2.1.113 の subagent は10分でタイムアウトします。
  • 長時間タスクはエージェントに分割指示するか、taskErrorThreshold を調整してエラー候補を可視化。

❌ ルール・メモリが効かない

症状：子エージェントがルールを無視して動作。

原因・対処：

  • claude -p 単体（--agent なし）で起動していないか確認。
  • Agent ツール（subagent_type）を並行タスクに使うと親コンテキストが漏れる（Issue #14118）。/csm-ask-agent を使用すること。

エラー自動収集とバグ報告

CSM は内部エラーを自動で ~/.claude/csm-errors.log に収集します。バグ報告時はコマンドパレットから「CSM: Report Bug (Create GitHub Issue)」を実行するだけで、以下が自動入力された Issue ページがブラウザで開きます：

  • CSM バージョン・VS Code バージョン・OS
  • Claude Code バージョン（claude.exe / cli.js）
  • 直近のエラーログ抜粋（匿名化済み）
  • エージェント定義の統計情報（名前・パスは含まない）
